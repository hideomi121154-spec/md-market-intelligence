# v3.7: 修理実績をMDの仕入れ上限につなげる試作

## 目的
整備データに含まれる同じ型式・年式・走行距離帯の不具合/整備の**対象車両数**と**故障確認車両数**を使い、試算上の未計上修理費を算出してMD仕入れ上限への影響を表示する。社内データにアクセスしたり自動取得したりするものではありません。

## データ分類
- **自己申告のコホート集計**：点検車両の重複のない対象母数、特定部位の故障を確認した車両数、1件あたり追加修理費を入力。集計対象期間、年式、距離、型式の統一が必要。入力者の責任で原典確認。
- **仮定**：入力者が仮定した割合と費用。実績や故障率として表現しない。
- 公開されるニュース見出し・SNS投稿件数から故障確率を自動生成しない。国交省の申告件数も購入・点検した母数なしでは故障率にしない。
- 車両の出自（レンタアップ/自家用）、整備水準、保証条件が違う車群の率を無検証で混ぜない。
- 個人情報・車台番号・顧客IDは入力しない。集計済みの情報のみ。

## 計算
同一条件に該当する故障部位ごとの期待修理費：
- 集計の場合：\`confirmed_affected_vehicles / inspected_vehicles × incremental_repair_cost\`
- 仮定の場合：\`assumed_probability × incremental_repair_cost\`
- 期待修理費合計を1円単位に切り上げ、元の「整備・再商品化＋追加リスク予備費」に含めた同リスク分だけ差し引いて、\`max(0,expected_cost - already_covered)\` を追加控除。
- 既存の「慎重シナリオ仕入れ上限」から追加リスクを差し引く。基礎の仕入れ上限計算には書き戻さない。

**重要：** 上記は税抜を想定した簡易的な期待値試算。複数部位間の同時修理・部品共用・事故車・修理再発・作業工賃差・保険等による費用分担がある場合は重複/誤差が起こり得る。同一部位への重複集計はエラーで停止。小母数（30未満）と仮定混合は警告する。30以上なら信頼できるという意味ではない。

## 使用方法
「計画」タブの「車種別修理実績 → MD仕入れリスク分析」を利用。
1. 任意のメーカー・車種・型式・年式範囲・距離範囲を入力。
2. 自己申告のコホート集計、または説明用の仮定を選び、車両数/費用/情報源/集計日を入力して端末に保存。
3. 対象車両条件を入力し、仕入れ上限の現行入力と比較。
4. JSONを書き出して自分で保存し、別端末へは追加復元できる。自動同期・外部送信はしない。

「架空のヤリス入力例」を表示しても**自動保存しない**。例の発生割合は実際のヤリスの故障率とは無関係。

## 検証・限界
- 入力者の「社内集計」というラベルは独立に検証できない。
- 修理歴が多い車ほど故障しやすい、とは断定できない（整備先・用途・車齢・距離・点検機会の選択バイアス）。
- 整備データが得られない場合は追加リスクを「不明」とする。0円試算は安全性・仕入れ承認ではない。
- 既存の消費者価格ノート・109件の記録・故障個別メモは別保存領域に保持し、移行・上書きしない。
- 将来的な実運用では、最小サンプル数、車台単位の重複排除、実績検証、アクセス管理、変更履歴、監査ログが必要。GitHub Pagesで非匿名の社内整備データを扱わない。
