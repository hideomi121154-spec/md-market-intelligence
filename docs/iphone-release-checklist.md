# MD MARKET v2.0.1：iPhone実機確認・本番公開チェックリスト

この文書は「実行済みの自動テスト」と「利用者のiPhoneで未実施の検証」を分けます。
**現時点では本番公開不可**。 `main` へPR #2をマージする前に、次の手順を実施してください。

## 1. 本番データのバックアップ（既存v1.9で先に）
- ホーム画面に追加したMD MARKETを開く。`データ` → `CSVをバックアップ` でファイルをiPhoneの「ファイル」などへ保存。保存したファイルを開いてデータ行を確認。
- `原本照合メモのバックアップ` → `照合メモを書き出す`。生成した全文を、CSVとは別のメモ・ファイルへ保存。
- Safariで開いた版も使っている場合、Safariとホーム画面版で同じデータが見えるとは限りません。双方にデータがある場合はそれぞれからバックアップ。
- バックアップが取れない場合、Safariの「履歴とWebサイトデータを消去」やPWA削除、iPhoneストレージ整理は行わず、開発者に知らせる。

## 2. まずGitHub Actionsの自動検証
- `tests/test_startup_diagnostics.js`：IndexedDBアップグレード・ブロック・タイムアウト・Service Workerの応答。
- `tests/test_inventory_observations.js`：同一条件の比較、異条件分離、JSON追加復元の保護。
- `tests/browser-smoke.cjs`：Chromiumモバイル画面で車両データの読み込み・在庫観測・バックアップ・オフライン再読み込み。
- WebKitはフォーム操作・記録・再読み込み・キャッシュ保存までの検証。Linux上のPlaywright WebKitでは擬似オフライン時のナビゲーションとfetchが内部エラーとなるため、**iPhone Safariのオフライン起動を検証済みとはしない**。

## 3. iPhone実機での公開前・公開直後の確認
- バックアップ済みであることを確認してからリリース作業を開始する。
- Safariとホーム画面アプリで、起動・タブ操作・既存の車両レコード件数・原本照合メモが保たれることを確認する。
- `相場`の「中古車の掲載台数｜在庫観測ノート」で、**あくまでテスト用観測値として**同一検索条件の2日分を入力し、件数差と増減率を確認。
- 地域を変えたとき、全国の記録と愛知県の記録が別系列になることを確認。
- JSON書き出し→端末外に保存→同じJSONを貼り付けて追加復元→0件追加となることを確認。
- Wi-Fiとモバイル通信を切った状態でホーム画面アプリを再起動し、画面と保存記録が見えるか確認。初回表示前にオンラインで一度起動する。
- ブラウザに旧画面が残った場合も、**先にデータ削除・アプリ削除・サイトデータ消去を行わない**。スクリーンショットとアプリ版・起動方法を記録する。

## 4. リリースと終了条件
- 上記項目がすべて通過し、既存の記録件数・照合履歴を保持し、オフライン再起動が正常であること。
- 起動停止・データ破損・記録消失があれば、機能リリースを中止しコード側の問題を検証する。ローカルデータを一括削除して復旧したことにしない。
- `main` へマージした後の画面表示版数は `v2.0.1` に統一し、GitHub Pagesの配信を確認する。
- 事故時のコード復旧はPRの変更を戻す。ただしコードのロールバック自体は端末内データ復元を保証しないため、バックアップを先に取る。

## 判断上の制約
在庫観測件数は特定サイトの検索結果に表示された掲載台数であり、実在庫・販売成約件数・売約率・USS実落札価格の代用にはしない。
