# MD MARKET — データ接続準備ラボ v0.1

このラボは、現行MD MARKETの本番PWAを**一切変更せず**、「将来正規データが取得できたら」業務判断機能に接続するための**独立した検証基盤**です。

## 現時点の完了範囲

- [x] 3種類のデータ契約：市場価格、在庫、商談需要
- [x] 架空サンプル（**全件合成**）で画面の動作を確認
- [x] JSON取込時の形式チェック、重複検知、取得区分の区別
- [x] 「小売実成約」だけの類似価格中央値・範囲（サンプルが少なければ出さない）
- [x] ユーザー入力による仕入れ上限の逆算
- [x] 地域別の在庫・問合せ・成約の**単純照合**
- [x] 実データと架空データを混ぜない（新しい持込データの取込時は全デモを排除）
- [x] 検証用の**時系列分割**ベースライン評価スクリプト
- [x] iPhoneのIndexedDB・localStorage・既存の109件記録にアクセスしない
- [x] 実験用のリッジ回帰学習・時系列train/calibration/test分割・ベースラインとのMAE比較・残差帯（**架空データでの機能検証のみ**）
- [ ] 実データでの予測精度実証・誤差区間の校正・本番予測モデル
- [ ] 在庫最適化モデル・需要予測・地域ごとの最適台数
- [ ] 車両画像からの傷/損傷検出の精度評価
- [ ] 許諾済み本番APIへの接続・定期データパイプライン
- [ ] 高品質な広告生成・車両マスタとの事実照合
- [ ] 法人の本番運用・権限管理・機密情報の保護

**重要**：「AIを完成」「仕入れ推奨の精度が確認済み」という意味ではありません。データが手に入った際に差し替え可能な構造と、評価の出発点を作っています。

## 起動

GitHub Pagesに反映した場合は `lab/data-ready/` を開く。
ローカルではリポジトリのルートで：

```sh
python -m http.server 8765
# http://localhost:8765/lab/data-ready/
node tests/test_data_ready.mjs
python lab/data-ready/train_price.py lab/data-ready/sample-data.json
```

UIは初期状態が**架空データ**であることを明示します。持ち込みJSONを読むとデモは消え、取り込んだデータだけになります。メモリ内に留まり、サーバーにアップロード・保存されません。

## データの受け口（JSON契約 v0.1）

1回の取込で1種類：

```json
{
  "dataset": "market",
  "records": [
    {
      "id": "record-001",
      "maker": "日産",
      "model": "ノート",
      "grade": "X",
      "year": 2022,
      "mileage_km": 30000,
      "price_jpy": 1350000,
      "date": "2026-10-01",
      "market_type": "retail_closed_sale",
      "source": "提供元の識別子（契約等で確認）",
      "license_status": "authorized"
    }
  ]
}
```

- `market_type`: `retail_closed_sale`（小売実成約）, `dealer_auction_closed`（業者AA実落札）, `retail_listing`（掲載提示額）, `buy_offer`（買取提示額）
- **掲載価格は実成約価格ではない**。小売実成約とAA実落札は別目的変数。混合モデルを作らない。
- `license_status: authorized` は**利用者が権利確認したという入力上の宣言**であって、アプリが契約や原本を保証したものではない。
- `synthetic` はデモのみ。実データ取込では拒否する。
- 共通の `id/maker/model/grade/source/license_status` に加え、以下が必要。

`inventory`（自社在庫）：

```json
{
  "dataset": "inventory",
  "records": [
    {
      "id": "stock-001",
      "maker": "日産",
      "model": "ノート",
      "grade": "X",
      "region": "愛知県",
      "status": "available",
      "date": "2026-10-01",
      "source": "自社記録（許諾確認）",
      "license_status": "authorized"
    }
  ]
}
```

`status` は `available`（在庫あり）、`reserved`（商談中）、`sold`（売約）。

`demand`（商談・販売記録）：

```json
{
  "dataset": "demand",
  "records": [
    {
      "id": "dem-001",
      "maker": "日産",
      "model": "ノート",
      "grade": "X",
      "region": "愛知県",
      "period_end": "2026-09-30",
      "inquiries": 12,
      "closed_sales": 4,
      "source": "自社集計（許諾確認）",
      "license_status": "authorized"
    }
  ]
}
```

複数種類の一括取込は `{"datasets":[...上記データセット...]}`。取り込む種類だけ置換し、他の種類は直近に読み込んだ実データを維持（デモは維持しない）。

## 将来のAIに必要なデータ

| 将来機能 | 最低限必要なデータ | 現時点の検証可能なもの |
|---|---|---|
| 買取・小売価格予測 | 車種/年式/距離/グレード/修復歴/装備と**実成約額**、取引日時、地域、十分な件数 | 過去の類似成約中央値、時系列テスト |
| AA仕入れ上限 | AA落札履歴＋販売実成約＋各費用・手数料・販売日数 | 手入力による逆算 |
| 地域別在庫最適化 | 在庫入出庫時刻、成約・問合せ履歴、値下げ、粗利益、移送費、欠品 | 地域別の在庫・問合せ件数 |
| 画像車両評価 | **権利を持つ写真**と人間が確認した傷・状態・査定ラベル、評価基準 | 未実装 |
| 広告文生成 | 正規車両マスタ、装備・状態、広告掲載ルール、商品説明の確認ログ | 未実装 |
| 故障費リスク | 型式、走行距離、整備費、実績、分母と重複排除 | 現行MD MARKETの故障ノート（本ラボには未接続） |

特に価格予測は、提供データに偏りがある場合、サンプルを増やしても精度は改善しないことがあります。ランダム分割ではなく**将来の取引を過去データで予測する時系列検証**が必要です。

## データ取得後の接続手順

1. データ契約・利用目的・転載・AI学習利用可否・個人情報を確認。
2. 提供元ごとに**専用の変換アダプター**を作り、このJSON契約に正規化。
3. 型式、修復歴、オプション、車台属性、単位、欠損、重複を品質検証（契約v0.2で追加）。
4. **掲載・成約・AA**を別々に保持。日付で過去/未来を分割し、予測誤差とバイアスを測る。
5. 誤差の許容範囲を実測で決め、低信頼なら「判断保留」を表示する。
6. モデルの推論結果を、既存の仕入れ上限計算・故障リスクなどに段階的に渡す。
7. 十分な結果が得られてから実務利用を検討。価格や買い付けの**自動承認は行わない**。

## v0.2 実験用の価格学習・予測精度検証

**現時点で実務投入可能な価格予測はありません。** データ取得後にモデル学習と精度評価を再実行できる道筋を実装しています。

```sh
# 全件架空の学習データを一時生成（実市場価格ではありません）
python lab/data-ready/generate_synthetic.py --output /tmp/md-market-synthetic.json

# 小売「実成約」の学習、過去/将来に分けた評価
python lab/data-ready/train_ml.py /tmp/md-market-synthetic.json --output /tmp/retail-price-report.json

# 業者間オークションの「実落札」は別モデルとして評価
python lab/data-ready/train_ml.py /tmp/md-market-synthetic.json \
  --market-type dealer_auction_closed --output /tmp/auction-price-report.json

# 自動テスト
python tests/test_data_ready_ml.py
```

作成した `/tmp/retail-price-report.json` はラボ画面の「価格モデルの学習・精度検証レポート」で読み取れます。JSON内の `model_artifact` は係数・特徴量・校正残差幅などの参考情報であり、Web画面では学習自体を実行しません。**企業・個人の私有価格データやモデル係数を公開GitHubにコミットしないこと。**

### 学習時のデータ分割

- 対象は `retail_closed_sale` または `dealer_auction_closed` のどちらか一方のみ。小売掲載や買取提示額は学習に使わない。
- メーカー/車名/グレード/地域を同じとするセグメントごとに独立学習。地域なしの記録は、地域ありの記録と混ぜない。
- 売買日を古い順に分割し、**学習約60% → 残差校正約20% → 最後の未知期間テスト約20%** を使う。同じ日付が境界をまたがない。
- 最低でも**60件かつ30日以上の異なる日付**を必要とするが、この件数はコードの動作を確かめるための閾値であり、業務に十分なサンプル数を意味しない。
- リッジ回帰の説明変数は車齢・走行距離・日付経過。基準モデルは学習期間内の単純中央値。比較指標はMAE（円）、中央値絶対誤差、MAPE、残差帯に入った観測割合。
- テスト期間の数値は係数や校正値へ混ぜない。テストの成績を見てモデルを選択・調整する反復は、別の未使用期間で再検証するまで過剰適合の危険がある。
- 90%を目標とする残差幅は時系列の市場変動下で90%を保証するものではない。あくまで**実験上の帯域**である。
- `license_status:authorized` はデータ利用権の自動検証ではない。匿名化や権利確認は人間側の責任。

### 未完成な部分

価格を推定して仕入れ可否を決める**意思決定APIや自動入札は未実装**です。将来、許諾された十分な実取引データが得られた場合、以下を別ステップで作る必要があります。

1. 型式・装備・修復歴・車両評価点・売買地域・車体状態・税区分などの追加特徴量。
2. 実際の取引価格と個別車両との一致確認、重複排除、業者間AAと小売の価格差の適切な分析。
3. 時間的なドリフト、車種別の誤差、未出現カテゴリへの対応、予測区間の校正。
4. 予測が不安定なときは**仕入れ判断を保留**する制御と、責任者による承認。
5. 実店舗の利益・販売日数・値下げ実績での独立検証。

この段階の価値は、「データがあれば学習から検証まで回る」ことを確かめる点にあり、「架空データで精度が高かったから実相場にも通用する」とは扱いません。

## iPhoneで「モデルの試験的な価格」を見る手順

1. GitHub Actions の `data-ready-lab-tests` が成功している実行結果を開き、Artifacts の `data-ready-synthetic-model-reports` をダウンロードしてZIPを展開する。
2. GitHub Pages の `/lab/data-ready/` をSafariで開く（本番ブランチへの統合後）。
3. 「6. 価格モデルの学習・精度検証レポート」で `data-ready-retail-report.json` を指定する。
4. レポート内で学習済みの車種・グレード・地域を選び、年式・走行距離・評価日を入力し、「この車両条件で試験的に推定」を押す。

ブラウザはPythonで学習した係数を再利用するだけで、**iPhone単体でモデルを学習するわけではありません**。合成データのモデル表示は架空の価格であり、実際の中古車相場と全く無関係です。

- 保存先はメモリのみで、画面を再読み込みすると読み込んだレポートは消えます。保存済みのMD MARKET本体データには影響しません。
- 学習時にない車種/グレード/地域、未観測の年式・距離や学習最終日から120日を超える評価日は**計算を保留**します。120日は本ラボの暫定的な拒否基準であり、120日以内なら精度が保証されるという意味ではありません。
- 画面の最初の架空レコード8件と、Actionsが別途生成する学習用合成取引レコードは**独立したデモデータ**です。分析結果が完全に一致する必要はありません。
- 現在提供しているのは小売成約またはAA落札についての**実験的な予測**であり、買取価格や入札上限を直接予測・推奨するAIではありません。
