# MD MARKET | iPhone単独PWA v1.9

**Windowsなし・同一Wi-Fi不要のiPhone向けアプリ**を作るための静的Web/PWAソースです。MAMO BOATと同じ GitHub Pages + PWA 方式を想定します。

## 何ができるか
- iPhone Safari → ホーム画面に追加して全画面で起動
- CSVファイルをiPhone内のIndexedDBに保存（Windows、Python、Supabase不要）
- 車種・メーカー・グレード・年式・走行距離・色・装備で絞り込み
- 業者間オークション / 消費者向けオークション / 小売掲載価格を区別
- 異なる取引市場の価格中央値を混ぜない
- 取引件数、車種数、価格中央値、月別推移、車両カード
- CSVバックアップ・復元（再取り込み）・重複除去
- Service Workerによる画面のオフラインキャッシュ

## 現時点でできないこと
- 車種別の**中古車**実落札価格・小売掲載価格の自動取得、カーセンサー掲載日数の計算
- 複数端末のデータ同期
- サーバーでの共同共有、SNSログイン
- iPhoneネイティブアプリとしてApp Storeから配布
- USS月次集計を個別車両データと結び付けた車種別仕入れ判断

**重要:** データはiPhoneのWebアプリ専用保存領域。Safariやホーム画面版の削除・ストレージ整理でデータが消える場合があるため、定期CSVバックアップが必要です。Safariとホーム画面版は保存領域が別になる場合があります。CSVはホーム画面から起動後に取り込むのを推奨します。

## 無料公開方法（GitHub Pages）

1. GitHubで新規リポジトリ `md-market-intelligence` を**Public**で作成（ソースだけを公開し、個人データや取引データはアップロードしない）。
2. このZIPの中の `index.html`, `app.js`, `storage.js`, `style.css`, `sw.js`, `manifest.webmanifest`, `icons/`, `.nojekyll` をリポジトリのルートにアップロードする。
3. Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)` → Save。
4. GitHubが発行した HTTPS URL をiPhoneのSafariで開き、共有 → ホーム画面に追加 → Webアプリとして開くをオン → 追加。
5. **ホーム画面のMD MARKETを開いてから**CSVをインポートする。

通常のURLは `https://<GitHubユーザー名>.github.io/md-market-intelligence/` の形式です。Pagesを実際に公開するまでは有効URLではありません。

## テスト（開発者向け）

Nodeで `node --check storage.js` / `node --check app.js`、Pythonで `python -m http.server 8765`、Chromiumで表示/CSV取り込みをテスト。Service Workerとホーム画面表示は HTTPS 上で検証する。

## v1.6 — 中古車価格の出典監査・個別記録（iPhone内）
- `データ` タブに個別の価格・年式・走行距離・メーカー・車名・グレード・市場区分・出典URLの手入力を追加。登録時は必ず**未検証**。CSV貼り付け・既存109件も変わらず未検証。

- **現時点で実落札価格の自動収集は未実装**。初期集計の照合済み件数が0件でも、既存109件のデータが消えたわけではない。
- 検証: `test_store.js` / `test_audit.js`、`.github/workflows/price-audit-tests.yml`でソースと車両登録UIの回帰チェック。

- 既存の `data/overseas-export-snapshot.json` を読み取り専用で利用。分類別の未収録国は0台ではなく `未収録`、国別累計未収録も同様。6区分の合計・国別累計との比率算出は禁止。**車名別・年式別・グレード別実輸出台数は提供しない**。
- 国選択、対象月選択、カテゴリー別輸出先上位ランキングを追加。ランキングの国をタップすれば該当国へ切替。
- 財務省2026年版 `第87類・中古乗用車` のHS 9桁統計番号に対応した**本人転記CSV取込**を追加（乗用車に限定したガソリン車の排気量別、ディーゼル、HV、PHEV、EV、その他（トラック・バスのHS番号は対象外））。`period,country,hs_code,units,source_url` の5列、`2026-MM` 形式、原典URLは税関またはe-Statに限定。これらは**公的統計の自動取得ではなく利用者の未検証転記**。
- 転記したHS数値は月・国・統計番号の組で検証し、既存行と異なる数値の上書きを禁止。転記CSVは別の `localStorage` キー `md-market-country-hs-manual-v1` へ追加保存し、CSVテキストを別途コピー・復元できる。既存のIndexedDB、車両CSV、照合履歴、輸出メモに変更なし。
- 2026年の公的HS分類： https://www.customs.go.jp/yusyutu/2026_01_01/data/j_87.htm 。e-Stat APIは登録・アプリIDが必要で、まだ自動接続されていない。初期のカテゴリー別台数はJUMV.NETが普通貿易統計から作成した公開ランキングの一部を既存JSONから表示する方式。
- テスト：`tests/test_country_export_mix.cjs`, `.github/workflows/country-export-mix-tests.yml`。iPhone Safari実機確認は残る。

## v4.2.0 — 財務省e-Stat公式データの自動更新（登録待ち）

- 「市場」→「世界各国｜中古車の輸出内訳」内に、独立した**公的統計**パネルを追加。`data/estat_used_vehicle_exports.json` から対象国×2026年各月×HS 9桁（中古乗用車のガソリン排気量別、ディーゼル、HV/PHEV、EV等）を表示。2026年の分類は税関第87類を使用。
- 初期ファイルの状態は `not_configured`、実績数値は**空**。実データ取得まで公的実測を装わず、既存の二次集計・本人転記もそのまま残す。
- `scripts/fetch_estat_used_car_exports.py` が公式 `getStatsList` → `getMetaInfo` → `getStatsData` を使用。**品別国別表・輸出・全国・2026年**の統計表タイトルを検証、表IDは最新公表から自動発見する。月次`数量1`だけ抽出し、単位 `NO` を必須確認。ページ送り、重複、形式変化、異常値、取得月の巻き戻りは更新停止。未公表の値や秘匿値は0台としない。
- APIは登録無料だがアプリケーションIDが必要。https://www.e-stat.go.jp/api/ で取得し、リポジトリの **Settings → Secrets and variables → Actions → New repository secret** へ名前 `ESTAT_APP_ID` で登録する。**チャットや公開コードにIDを送らない**。登録後は GitHub Actions → `Official e-Stat Japanese used-car export updates` → `Run workflow` で最初の検証実行。
- `.github/workflows/estat-used-exports.yml` は毎日01:26 UTC（日本時間10:26頃）に確認（実際の起動時刻は遅れることがある）。未登録時は正常なスキップとしてデータを更新しない。検証成功＋ファイル変更時のみ `main` にコミット。API構造が変更されても以前の正しいJSONを維持する。
- e-Stat JSONの数値は「日本からその国への中古乗用車の**対応16個のHS分類の収録行**」であり、日本の中古車輸出全車種全種類や特定車種名（ヤリスなど）の実数ではない。HS分類で未収録の区分は0とせず`未収録`として表示。既存 JUMV.NET ランキングとは統計定義・データ期間が違うため合計や横並びの自動率計算をしない。
- 既存の車両レコード・照合履歴・在庫観測・端末メモには**読み取りも書き込みもしない**。 Service Workerのファイルキャッシュ識別子だけを変更。
- テスト：`tests/test_fetch_estat_exports.py`（API応答モックで出典/単位/欠測/改定を検査）、`tests/test_estat_exports.cjs`（データと画面・オフラインファイルの検証）。新規APIの実応答はアプリID設定後に確認できるため、現時点でリアルタイム接続成功は未確認。

## v4.3.0 — 世界各国 × メーカー × 車種｜海外輸出需要モニター

- 画面の「ロシア × トヨタ ヤリス」固定パネルを「世界各国 × メーカー × 車種」選択式に更新。初期選択は従来と同じ**ロシア × トヨタ × ヤリス**。機能は `global-export-model.js` と `data/export-model-catalog.json` に分離し、スマートフォンの操作性を確保。
- UIカタログは**55か国**（既存国別二次統計で収録された18か国＋候補国。候補国で輸出実績が存在すると主張しない）、**9メーカー・81車名**。集計を追加できるよう動的に公式e-Stat収録国や端末の原典付き車種メモの国も選択可能。カタログの網羅性や輸出先への輸出可否は保証しない。
- 選択した国について、既存JUMV.NET二次集計の**全車種・全区分**2026年1〜9月国別累計（上位10国のみ）、2026年9月の普通車/HV/EV/軽/トラック/バスの国別月次（各分類上位5国のみ）、e-Stat公的HS分類（**API ID設定が済んだ場合のみ**）を**統計母集団・期間ごとに分離**。分類別の未掲載を0台や車名別の人気として扱わない。
- 選択車種の参考として2021〜25年の国内**新車**年次統計を登録車（自販連、うち2021年は二次転記）および軽自動車（全軽自協）の既存データから表示。未収録年・未収録モデルは0台ではない。派生モデル・同名車種は一次資料の集計対象を要確認。
- 現段階で**国×車名の公式・直接的な実輸出台数は全組み合わせで `null/未取得`**。国別累計や国内新車数から推定・按分しない。既存 `md-market-crossborder-model-notes-v1` に一致する車名と国の本人入力記録があれば「**未検証の本人記録**」としてのみ掲載。元記録・端末保存形式を編集・移行しない。
- ロシア選択時だけJETRO公表の2025年日露中古乗用車輸出合計を補足し、ロシア×トヨタ時のみAUTOSTATの「ロシア国内全トヨタ中古車販売」を補足。これらを車種実績や2026年の集計とは混ぜない。ロシアの経産省輸出規制の原典リンクを表示し、**車名だけで合法／違法を決めない**。
- 「この国の車両タイプを確認」で従来の国別内訳パネルへ移動。「原典付き記録を追加」で既存の端末内本人記録フォームへ国・メーカー・車種を転記。選択履歴のみ別キー `md-market-global-export-model-select-v1` に保存し、個人の車両IndexedDBや既存メモを削除しない。
- 元の `russia-yaris.js` と出典JSONは後方互換・ロシア参考統計の検証用として残すが、固定UIは表示しない。iPhone表示・オフラインキャッシュをv4.3に更新。
- 検証：`tests/test_global_export_model.cjs`、`.github/workflows/global-export-model-tests.yml`、既存の国別・ロシア資料・PWA回帰試験。実iPhone Safariでの手動確認は別途必要。

## v4.4.0 — 国別比較と車種別根拠・国内掲載価格の照合

- 「世界各国 × メーカー × 車種」モニターに**国別比較｜選択車種の根拠を確認**を追加。国別輸出累計の上位10か国、選択車種の本人記録がある国、選択可能なすべての国の3表示を切替。国を選択すると上のモニターへ遷移して統計を表示。
- 比較順位は**2026年1〜9月の「国全体（全車種）の輸出合計」順**。**選択車種の需要・販売・輸出ランキングではない**。国別合計が未収録の場合はゼロではなく「未収録」。分類別の掲載は2026年9月・各カテゴリー上位5か国の範囲を明示し、国全体と合算しない。
- 既存 `md-market-crossborder-model-notes-v1` の**国・メーカー・車名が厳密に一致**する本人転記記録だけを比較欄に表示し、原典へのリンクと対象月を示す。どの記録も未検証。最新月に異なる対象範囲や値が併存する場合は競合として明示。本人記録を公式の車種別輸出実績に昇格させない。記録がない場合も需要0とはみなさない。
- 端末に保存済みの `md-market-model-price-monthly-v1`（カーセンサーが公表した**国内中古車のモデル別平均支払総額・月間延べ掲載台数**の本人転記）を選択車種ごとに表示。同一モデル区分かつ連続する月の記録に限って前月差を参考表示。実落札価格・実成約額・海外での車種別価格ではない。モデル区分の異なる記録は集計しない。データがないときは「未記録」と表示。
- 既存のIndexedDB、本人の海外根拠記録、国内価格記録は**読み取り専用**。新しいユーザー個別データベースは作らず、変更するのは画面とService Workerキャッシュのみ。スクレイピングなし、架空値なし、e-Stat API未設定なら公式実績は未設定のまま。
- 回帰テスト `tests/test_export_evidence_desk.cjs` とGitHub Actionsを追加し、iPhone相当のChromium/WebKitテストでも比較フィルターと切替を確認。

## v4.5.0 — 47都道府県の新規求人数を公的Excelから自動収録

- 公式対象は厚生労働省 e-Stat「一般職業紹介状況（00450222）／長期時系列表12／第12表-1（パートタイムを含む一般）／都道府県**受理地別**／新規求人数／**原数値**」。パートタイム除外・常用・求人広告媒体数・求職数・就業地別とは異なる。公表一覧: https://www.e-stat.go.jp/stat-search/files?cycle=1&layout=dataset&page=1&toukei=00450222&tstat=000001020327
- `scripts/fetch_prefecture_jobs.py` は公式一覧から**表12の題名・年月・公表日・ファイルID**を照合し、e-Statが掲載するExcel原本をダウンロード。第一シートの表題、47県の E〜AY 列の順番、D列全国合計、単位「人」、月次の年/月、47値の合計＝全国値を確認した場合のみ公的数値としてJSONに書き出す。年次・年度平均の行は月次に混ぜず、直近最大36か月を収録。元ExcelのSHA-256を保持し、追加訂正時も照合可能。
- `.github/workflows/prefecture-jobs-sync.yml` はPRで原本を実際にダウンロードして検証。main更新・毎週月曜・手動実行時には検証済みファイルに変更がある場合だけ `data/prefecture_jobs.json` をコミットする。構造や公表日、47合計が食い違う場合は**失敗終了して旧データを維持**する（APIキー不要）。
- 市場→「求人動向｜47都道府県」にデータ出典セレクターと、選択県の最大24か月の折れ線を追加。前月比・前年同月比・増減率の県別順位は既存の計算を維持。季節性のある原数値と同じ月の前年比を区別。過去月に比較先がない場合は割合を出さない。
- 端末内に先に取り込んだ本人データは維持するが、公式ファイルが存在する場合は**公式を標準表示**。本人入力は別の選択肢から閲覧でき、本人取込後は「未照合」を明示。既存データを削除しない。価格/在庫/個人記録には変更なし。
- 新規 `tests/test_fetch_prefecture_jobs.py` でダミーExcelの解析・列順・全国合計・比較年月の検証。既存 `tests/test_prefecture_jobs.cjs` とiPhone WebKit/Chromiumブラウザ試験も回帰確認。
